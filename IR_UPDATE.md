1. Open [sanity.io/manage](https://www.sanity.io/manage) → project **Incontri Ravvicinati** → **API → Webhooks → Create webhook**. Name: `Aggiorna sito e sitemap`; dataset: `production`; enable it. [Official webhook guide](https://www.sanity.io/docs/content-lake/webhooks).
2. URL: `https://www.incontriravvicinatimag.it/api/revalidate` (use `SITE_URL` if changing domain); HTTP method **POST**; triggers **Create, Update, Delete**. Leave draft/version triggers disabled. No custom Authorization header or query-string secret.
3. Filter: `_type in ["article", "author", "rubrica", "issue", "siteSettings", "sectionSettings", "sanity.imageAsset"] && !(_id in path("drafts.**")) && !(_id in path("versions.**"))`.
4. Projection: `{_id, _type}`. **Secret:** exactly the value stored as `SANITY_REVALIDATE_SECRET` on Vercel. Save; after the website deployment, inspect webhook delivery logs for HTTP 200 on the next normal content publication. The handler intentionally returns 503 until its secret is configured, 401 for an invalid/missing signature, 400 for invalid content.
5. Google Search Console → the production-domain property → **Sitemaps** → submit `https://www.incontriravvicinatimag.it/sitemap.xml`. Search Console access/indexing was not changed by this batch.
